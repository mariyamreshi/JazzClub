# ข้อเสนอแบ่งงานทีม 3 คน

อิงเจ้าของ milestone เดิมใน proposal ปรับได้ตามความถนัดของทีม เจ้าของงานมีหน้าที่ส่งมอบและประสานงาน ไม่ได้หมายความว่าต้องทำทุกอย่างคนเดียว

| คน | งานหลัก | ผลงานที่ตรวจรับได้ | งานที่ช่วยแบ่งภาระ |
| --- | --- | --- | --- |
| Garnet | โครง backend, การเชื่อม MySQL, schema/seed หลังรีวิว ERD, API การจองและออเดอร์/ชำระเงิน | API ต่อฐานข้อมูลได้ และ flow จอง → สั่ง → บันทึกชำระเงินผ่าน | review API ที่ Fifa/Mary ทำ และรวมระบบ |
| Fifa | นำ ERD/3NF, หน้าลูกค้า/โต๊ะ/จอง, หน้าศิลปิน/การแสดง/attendance | ERD + data dictionary และหน้าจองที่ใช้ API ได้ | ทำ API artists/shows/attendance ตามตัวอย่างจาก Garnet และรายงานโต๊ะว่าง |
| Mary | หน้าพนักงาน/เวร, เมนู/stock, ออเดอร์/ชำระเงิน และหน้ารายงาน | หน้าปฏิบัติงานที่เชื่อม API และแสดงรายงานได้ | ทำ API employees/shifts/menu ตามตัวอย่าง และ query ความพร้อม/ออเดอร์กับการชำระเงิน |

ให้ Garnet ทำตัวอย่าง CRUD หนึ่ง resource ร่วมกับทีมก่อน แล้ว Fifa/Mary ใช้รูปแบบเดียวกันทำ API ที่รับผิดชอบ วิธีนี้ลดงาน backend ที่กองอยู่คนเดียว ทุกคนช่วยทำ sample data ของฟีเจอร์ตัวเอง โดย Garnet รวม `seed.sql`

## ตำแหน่งไฟล์ใน MVC

- งานฐานข้อมูล: `database/` และ `docs/erd/`
- งาน backend: `src/models/`, `src/controllers/`, `src/routes/` และ `src/config/`
- งานหน้าเว็บ: `src/views/`, `public/css/`, `public/js/` และ `public/images/`
- แต่ละคนแก้ไฟล์ตามฟีเจอร์ที่รับผิดชอบในโฟลเดอร์ร่วมเหล่านี้ เช่น `shows.model.js` กับ `shows.controller.js` ไม่จำเป็นต้องแบ่งคนหนึ่งทำเฉพาะ Model อีกคนทำเฉพาะ Controller

## ลำดับงานตาม proposal

| Milestone | เจ้าของตาม proposal | วิธีทำร่วมกัน |
| --- | --- | --- |
| Week 4: ERD และ 3NF | Fifa | ทุกคนตกลงกติกาจอง/stock/พนักงานและ review schema |
| Week 6: Database + sample data | Garnet | แบ่งสร้างข้อมูลจำลอง อย่างน้อย 20 แถวต่อตารางหลักตาม milestone ที่ทีมเขียนไว้ |
| Week 7: Backend API | Garnet นำ | Fifa/Mary ทำ API ของฟีเจอร์ที่รับผิดชอบ พร้อมตรวจใน Postman |
| Week 8: Frontend + 3 reports | Fifa และ Mary | Garnet ช่วยเชื่อม API แก้ query และตรวจผลรวม |
| Week 9: Demo และรายงาน | ทั้งทีม | ทุกคนอธิบาย schema และสาธิต flow ที่รับผิดชอบได้ |

Week เหล่านี้คือลำดับ milestone ในเอกสาร ไม่ใช่การยืนยันวันส่งปัจจุบัน ให้เติมวันที่จริงร่วมกัน

## ทำงานพร้อมกันโดยไม่ต้องรอ backend ทั้งหมด

1. ตกลงชื่อ field, URL, รูปแบบวันที่ และตัวอย่าง JSON ใน `docs/api-contract.md`
2. Fifa/Mary ทำหน้าเว็บด้วยข้อมูลจำลองตาม JSON ที่ตกลง ขณะ Garnet ทำฐานข้อมูลและ API ชุดแรก
3. เชื่อมหนึ่ง flow ให้ครบ เช่น ดูโต๊ะ → สร้างการจอง → แสดงผล ก่อนเพิ่มงานส่วนอื่น
4. ทำรายงานทั้งสามไปพร้อมกับฟีเจอร์ที่ให้ข้อมูล ไม่เลื่อนไปท้ายโครงการทั้งหมด

## ข้อตกลง Git ที่เสนอ

- แยก branch ตามงาน เช่น `feature/reservations-ui`, `feature/shows-api`, `feature/database-schema`
- ใช้ pull request และให้เพื่อนอย่างน้อยหนึ่งคน review ก่อน merge เข้า `main`
- เปลี่ยน API/schema ให้แจ้งทีมและอัปเดตเอกสารใน PR เดียวกัน
- ไฟล์ส่วนกลาง เช่น `database/schema.sql`, `src/app.js`, `src/routes/index.js` และ `public/js/api.js` ให้ตกลงผู้แก้ในแต่ละช่วง
- งานเสร็จเมื่อหน้าที่เกี่ยวข้องเชื่อม API ได้ ตรวจข้อมูลผิดพลาดได้ และอธิบายผลต่อฐานข้อมูลได้

## กรณีทดสอบร่วมกันเมื่อมี implementation

- จองโต๊ะช่วงเวลาซ้อน รวมคำขอพร้อมกัน และการคืนโต๊ะหลังยกเลิก
- ออเดอร์หลายรายการ ใช้ราคาตอนสั่ง ยอดชำระเงิน และผลต่อ stock
- show ที่พนักงาน/stock พอและไม่พอ โดยอ้างอิงเกณฑ์ที่ทีมตกลง
- รายงานการจองที่ยังไม่มีออเดอร์ และออเดอร์ที่ยังไม่ชำระเงิน
